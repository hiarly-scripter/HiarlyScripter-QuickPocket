## Scope

P1 hotfix for asymmetric MapValuable/TAB marker state when Player 2 pockets an item and the host/master remains as observer.

No changes intended for collision, damage, audio, timeout, HUD/loading, SafeDrop, Saw/Blade blocking, REPOConfig, cart drop, strings, or the request/ACK flow beyond guaranteeing local marker hide on the host.

## Diagnosis

v1.0.11 centralized the pocketed item state and `HandleHostPocketRequest` already called `HidePocketedItemState(..., HideMode.HostHosted, "HostPocketRequest", snap)`.

The remaining asymmetry was in `ProcessRemotePocketUpdate`: the master returned immediately for every `QP_{actor}` RoomProperties change. That early return was correct for avoiding duplicate remote restore on removal/drop, because the host already restores with the authoritative drop position in `HandleHostDropRequest`. However, it also prevented the host from treating `QP_2` additions as observer updates and from reapplying local MapValuable marker hide when the room property added a ViewID for Player 2.

## Changes

- `ProcessRemotePocketUpdate` now distinguishes master additions from removals.
- On master additions, the host finds the hosted snapshot for the remote actor and reapplies `HidePocketedItemState(..., HideMode.HostHosted, "RoomPropertiesHostAdd", snap)`.
- Master removals still skip remote restore to avoid overriding the host-authored drop position.
- Map marker log side labels now map modes into user-facing sides:
  - `HostHosted` -> `Host`
  - `OwnerAck` -> `Owner`
  - `Remote`/`LateJoin` -> `Observer`
- Version updated to `1.0.12-test` in csproj, BepInPlugin, and startup log.

Expected logs:
- `[QP:MapMarkerState] hide actor=2 viewID=... side=Host found=True disabled=True`
- `[QP:HideState] viewID=... mode=HostHosted reason=RoomPropertiesHostAdd ... marker=True`
- `[QP:MapMarkerState] restore actor=2 viewID=... side=Host finalPos=... result=OK/SkippedStale`
