## Bug A — HUD Loading: causa raiz e fix

**Causa raiz confirmada:**
- `RunIsLevel()` fica `true` antes de `LoadingUI.levelAnimationCompleted` ser refletido corretamente no polling
- O `_cachedIsLoading` (polling de `levelAnimationCompleted` por reflexão) ficava `false` cedo demais — a animação de loading "completava" internamente antes da tela preta sumir visualmente
- Manager antigo podia religar HUD apenas com a verificação de singleton (já corrigido), mas o manager ATUAL também liberava HUD cedo

**Fix aplicado:**

1. **Generation/latch system:**
   - `static int _hudGeneration = 0` — incrementado em qualquer transição
   - `int _managerGeneration = -1` — capturado no `Awake()` com valor atual de `_hudGeneration`
   - Guard em `Update()`: `if (_managerGeneration != _hudGeneration) return;`
   - Guard em `ShouldRenderHud()`: `if (_managerGeneration != _hudGeneration) return false;`
   - `HandleLevelChange()` incrementa `_hudGeneration++` e atualiza `_managerGeneration`
   - `OnSceneLoaded()` incrementa `_hudGeneration++` e atualiza `_managerGeneration`
   - `ClearAllState()` incrementa `_hudGeneration++` e atualiza `_managerGeneration`

2. **Flag `_loadingAnimDone`:**
   - `false` por default (fail-closed)
   - Setado `true` pelo patch `LoadingUI.LevelAnimationComplete()` via `OnLoadingAnimationComplete()`
   - Fallback: se `IsLoadingActive() == false && RunIsLevel() == true`, também seta `true`
   - Gate de release em `Update()`: `if (_cachedRunIsLevel && _loadingAnimDone)`
   - Check em `ShouldRenderHud()`: `if (!_loadingAnimDone) return false;`

3. **Novos patches:**
   - `LoadingStartPatch`: `LoadingUI.StartLoading()` → `PocketManager.OnLoadingStarted()` — suprime HUD
   - `LoadingAnimCompletePatch`: `LoadingUI.LevelAnimationComplete()` → `pm.OnLoadingAnimationComplete()` — seta `_loadingAnimDone = true`

**Logs esperados:**
```

[QP:HUDState] gen=N allowed=false reason=LevelChangeStart
[QP:HUDState] gen=N allowed=false reason=StartLoading          ← patch StartLoading
[QP:HUDState] gen=N loadingAnimDone=true reason=LevelAnimationComplete  ← patch LevelAnimationComplete
```

## Bug B — MapValuable marker posição errada: causa raiz e fix

**Causa raiz confirmada via reflection:**
- `MapValuable`: sem `Update()`, usa coroutine `Logic()` iniciada em `Start()`
- `SetActive(true)` → Unity chama `Start()` → `StartCoroutine(Logic())`
- A coroutine lê `target.transform.position` para posicionar o marker
- **No código anterior:** `SetActive(true)` era chamado no passo 4d, ANTES do item ser posicionado (passo 5/7)
- Quando Logic() rodava, `target.transform.position` ainda apontava para a posição original (bolso)

**Fix aplicado:**
- Removido bloco 4d de `RestoreSnapshot()`
- Adicionado passo 8 (NOVO) — APÓS o item ser posicionado (após passo 7):
  ```csharp
  // 8. Reativar MapValuable DEPOIS do item estar posicionado
  if (snap.MapValuableMarker != null && snap.MapValuableMarker.target != null)
      snap.MapValuableMarker.gameObject.SetActive(true);
  ```
- Verificação `target != null` antes de reativar — evita fantasma e NRE se item foi destruído

**Fix para sub-bug (item quebrado enquanto pocketado):**
- Em `EnforcePocketState()`, quando `go == null` (item destruído):
  ```csharp
  // Desativar marker para evitar fantasma na posição original
  sn.MapValuableMarker.gameObject.SetActive(false);
  ```

**Logs esperados:**
```
[QP:MapMarker] item=X method=MapValuable markerFound=True        ← pocket
[QP:MapMarker] item=X disabled=True                              ← hide
[QP:MapMarker] item=X restore=True method=AfterPosition targetPos=(...) markerPos=(...)  ← restore
[QP:MapMarker] item destroyed, marker hidden item=X              ← item quebrou
```

## Bug C — Glow/brilho boombox: causa raiz e fix

**Causa raiz confirmada via reflection:**
- `ValuableBoombox` (extends `Trap`): campos `light1` (Light), `light2` (Light), método `Update()`
- `MusicalValuableLogic`: campo `physGrabObject`, método `Update()`
- O `Update()` desses componentes continuava rodando durante o pocket (apenas `PhysGrabObject` era desabilitado)
- `ValuableBoombox.Update()` pode religar `light1`/`light2` baseado em `trapActive`

**Fix aplicado:**
- Adicionadas keywords em `SaveSnapshot()` para `ModifiedMapBehaviours`:
  - `"Boombox"` → captura `ValuableBoombox`
  - `"Musical"` → captura `MusicalValuableLogic`
  - `"Glow"`, `"Flash"`, `"Blink"` → captura outros comportamentos de efeito visual
- `ApplyHide()` desabilita esses componentes (`.enabled = false`)
- `RestoreSnapshot()` os restaura ao estado original

**Log diagnóstico completo em ApplyHide:**
```
[QP:HideComponents] item=X lights=N audio=N particles=N trails=N behaviours=N behavioursDisabled=N
```
