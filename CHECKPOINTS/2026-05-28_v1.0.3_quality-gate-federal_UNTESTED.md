## 2. Fixes aplicados — detalhes

### Fix 1 — Versão 1.0.2 → 1.0.3

---

### Fix 2 — HandlePocketKey protegido contra NPE (P0)
**Arquivo:** `src/Core.cs`

**Antes:** `SemiFunc.PhysGrabberLocalIsGrabbing()` chamado sem proteção. NPE do REPO
escapava para `Update()` (confirmado no stack trace do Player 2).

**Depois:** corpo inteiro de `HandlePocketKey()` dentro de `try/catch`:
```csharp
try
{
    if (_isPocketing) return;
    ...
    if (SemiFunc.PhysGrabberLocalIsGrabbing())
    ...
}
catch (System.Exception ex)
{
    QuickPocketPlugin.Log.LogDebug("[QP:HandlePocketKey] excecao: ...");
}
```

---

### Fix 3 — TryPocket catch block tag padronizada (P0 diagnóstico)
**Arquivo:** `src/Core.cs`

Antes: `"[QuickPocket] PhysGrabberLocalGetGrabbedPhysGrabObject excecao: ..."`
Depois: `"[QP:TryPocket] fallback=ExceptionCaught source=PhysGrabberLocal exception=..."`

---

### Fix 4 — Log diagnóstico precoce em TryPocket (P0 diagnóstico)
**Arquivo:** `src/Core.cs` — inserido após `ResolveRootPgo`, antes da verificação de inimigo

```

```

---

### Fix 5 — Log de ownership com variável policy (P0 diagnóstico)
**Arquivo:** `src/Core.cs`

Adicionado campo `policy=IsMine|Takeover|DirectFixed` no log MP:
```

```

---

### Fix 6 — DropConfirm log de estado físico (P1 restore integrity)
**Arquivo:** `src/Core.cs` — inserido após validação de posição OK, antes de finalizar

```

```

Permite diagnosticar itens atravessáveis após drop sem precisar de teste cego.

## 7. Limitações conhecidas desta versão

- **Denylist por nome é heurística:** "Door" bloqueia qualquer item com essa substring. Se existir item legítimo "Cardboard Box Door Prop" que deveria ser pocketável, precisará ser refinado.
- **"Upgrade" é substring ampla:** pode bloquear itens com "Upgrade" no nome que sejam loot legítimo. Refinamento pendente.
- **Player 2 não é dono dos itens:** Drop sincronizado funciona via Room Properties, mas o item restaurado pode ter física ligeiramente diferente do estado original (limitação de v1.0.x, documentada).
